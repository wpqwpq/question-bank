## 0. 结论

| 问题 | 结论 |
|---|---|
| 能不能做「按规范接收文件」的接口？ | 能。技术上没有任何障碍，现有认证/审计/原子写/学科隔离都可直接复用 |
| 做了能替代 `rsync` 吗？ | **不能**。首入库（含 PDF、整卷 500MB）必须继续走 rsync |
| 那做了解决什么？ | 解决**题级更新**的四类事故（见 §1），这才是你现在真正踩坑的地方 |
| 建议形态 | `POST /api/ingest/bundle`，body 是一个 **zip 题包**（内含 manifest） |
| 工作量 | 一期约 300 行后端 + 一个 60 行客户端脚本，半天到一天 |

**核心判断：不要做「push_one.sh」，要做「带校验的题包提交」。**
脚本只帮你省路径，接口帮你挡错误。省路径这件事你我已经不太会错了，真正会错的是：
漏传 assets、`cut.json` 串味、把云端切出来的子图覆盖没、重传后老师的「已核对」还亮着。

## 1. 接口相对 rsync 的真实收益

| 事故 | 现在 rsync 的表现 | 题包接口怎么挡 |
|---|---|---|
| **漏传 assets** | 图 404，或残留旧图，静默无感 | 校验 `q14.md` 的 `image:` / `layout:` 指向的文件必须在包内或云端已存在，缺一个直接 422 |
| **图与 layout 不配套** | 完全无感（坐标错位才被发现） | 用 Pillow 读 webp 实际像素，比对 `layout.json` 的 `size.w/h`，不等就 422 |
| **cut.json 串味** | 本地旧 cut.json 整份覆盖云端，别的题切割数据倒退 | 包内只允许 `cut.patch.json`（仅本题），服务端按 `number` **逐项 merge**，其他题一个字节不动 |
| **覆盖掉云端子图** | `rsync --delete` 或整目录传 → 子题图被删、子题 md 指向空图 | 默认 **upsert** 语义：只写包内文件，**绝不删包内没提到的文件**；要删必须显式 `replace` |
| **重传后「已核对」假亮** | `confirmed.json` 按 qid 存，不感知文件变化（已记在 10-17 日志的待办里） | 提交时对比覆盖前后 sha256，**内容真变才撤该题全部单元确认** |
| **谁在什么时候传了什么** | 无记录（只有 ssh 日志） | 写 `_audit`：包 sha256、文件清单、字节数、force 标记、操作人 |
| **误操作不可预演** | 传了就传了 | `?dry_run=1` 先返回「将新增/覆盖/不动/删除」清单，看一眼再提交 |

反过来 rsync 的不可替代之处，也要认：
- 断点续传、大文件（PDF 531MB）、目录级秒同步；
- 首次入库本来就不是「传文件」，是跑 `cut_paper.py → render_questions.py → import_papers.py` 流水线；
- `-a` 的 mtime 比对就是天然幂等。

**所以边界是：**

```
整卷首入库 / 换源重切 / 批量刷图（有 PDF）  →  rsync      （不变）
单题修正 / 少量题重切 / 补图补 layout       →  题包接口    （新增）
```

## 2. 协议规范

### 2.1 题包结构

zip，扁平结构，路径 = 相对卷目录：

```
2020-jan-wph11-q14.zip
├── manifest.json              ← 必须，且必须是这个路径
├── q14.md
├── assets/q14.webp
├── assets/q14.layout.json
├── q14-a.md                   ← 子题（若有）
├── assets/q14-a.webp
├── assets/q14-a.layout.json
└── cut.patch.json             ← 可选，只含本题的切割项
```

**白名单正则**（其余一律 422，含 `source.pdf`、`paper.md`、绝对路径、`..`、zip 内符号链接）：

```
^(q\d+\.md|q\d+-[a-z0-9]+\.md)$
^assets/(q\d+|q\d+-[a-z0-9]+)\.(webp|png|layout\.json)$
^(cut\.patch\.json|cut\.json)$
```
> `cut.json` 整份只在 manifest 声明 `"cut":"replace"`（整卷重切）时允许。

### 2.2 manifest.json

```json
{
  "schema": 1,
  "board": "edexcel",
  "qualification": "a-level",
  "subject": "physics",
  "paper": "2020-jan-wph11",
  "questions": ["14"],
  "mode": "upsert",
  "cut": "merge",
  "base": {
    "q14.md": "sha256:6b851b6a...",
    "cut.json": "sha256:d547291c..."
  },
  "files": [
    {"path": "q14.md",                  "size": 5153,   "sha256": "..."},
    {"path": "assets/q14.webp",         "size": 182334, "sha256": "..."},
    {"path": "assets/q14.layout.json",  "size": 2411,   "sha256": "..."}
  ],
  "note": "重切 q14，题干多出两行"
}
```

- `mode`: `upsert`（默认，不删） | `replace`（删该题 `qNN-*.md` 及其 assets 再写，等于「这题重做」）
- `cut`: `merge`（默认） | `replace` | `none`（不动 cut.json）
- `base`: **乐观锁**。服务端取现有文件 sha256 比对，不一致 → 409，除非 `?force=1`

### 2.3 接口契约

```
POST /api/ingest/bundle?dry_run=1|0&force=0|1
Authorization: Bearer <API Key>
Content-Type: application/zip
Body: <zip 字节>
```

| 状态码 | 含义 |
|---|---|
| 200 | 成功（`dry_run=1` 时为「预演成功」） |
| 400 | 包损坏 / manifest 缺失 / 路径非法 |
| 401 / 403 | 未认证 / 无上传权限 |
| 404 | 学科不可见（沿用「跨科一律 404」的既有约定） |
| 409 | `base` 指纹不匹配（云端更新过），或该题被标「有误」 |
| 413 | 超过大小上限（单包 24MB，解压后 64MB，条目 ≤ 200） |
| 422 | 校验不通过（缺图、坐标尺寸不符、front-matter schema 错、题号不存在） |

响应：

```json
{
  "ok": true,
  "dry_run": true,
  "paper": "2020-jan-wph11",
  "questions": ["14"],
  "plan": {
    "create":    ["assets/q14.webp"],
    "update":    ["q14.md"],
    "unchanged": ["assets/q14.layout.json"],
    "delete":    [],
    "cut": { "replaced": ["14"], "kept": ["1","2","3"] },
    "confirm_revoked": ["edexcel-a-level-physics-2020-jan-wph11-q14"],
    "flag_cleared": ["edexcel-a-level-physics-2020-jan-wph11-q14"]
  },
  "warnings": ["云端没有 source.pdf，跳过源一致性校验（符合预期）"]
}
```

> `plan` 里把「不动 / 不删」也列出来，是刻意的——你现在最担心的就是「会不会把子图删了」，
> 那就让接口每次都明确回答「没删」。这一行字比十句文档都管用。

## 3. 服务端流水（8 步，锁只占最后一段）

```
① 认证 + 权限          Bearer Key → Ident，要求 can_ingest
② 收包到临时目录        data/.ingest/<uuid>/ ，边解压边限流（大小/条目数/路径）
③ 逐文件 sha256         与 manifest.files 比对，不符 → 422
④ 结构校验            路径白名单、front-matter JSON Schema、id 与路径一致、subject 权限
⑤ 引用与配套校验       image/layout 存在性、layout.size vs webp 实际像素、
                      cut 题号在整卷题号集合内、子题 parent 指向存在
⑥ 冲突检查             base 指纹；replace 模式下确认要删的东西（进 plan）
⑦ dry_run 出口        直接返回 plan，删临时目录，结束
⑧ 提交                —— 从这里开始持 store._lock ——
                      a. 内容真变的文件：先写 <name>.tmp 再 os.replace（按字节写，不 decode）
                      b. 删 replace 模式下该题的旧子题 md 与 assets
                      c. cut.patch 按 number merge 后写回
                      d. paper.invalidate() + store._index_put/_index_drop/_drop_meta
                      e. review 批量撤确认（仅内容真变的单元）
                      f. auth.audit("ingest.bundle", qid, {...})
                      g. 退出锁 → 删临时目录
```

**为什么锁只占第 ⑧ 步**：`store._lock` 是进程内 RLock，全打标台共用。解压和校验动辄几十毫秒到几百毫秒，
如果在锁里做，老师那边会明显卡一下。规则是：**慢活无锁，提交持锁，持锁期间只做 rename。**
提交阶段是纯本地文件操作，15 个文件也就几毫秒。

**为什么按字节写**：本项目已有教训——`Path.write_text()` 在 Windows 上会写 `\r\n`，把 md 的换行改掉。
云端是 Linux 没这问题，但包是在 Windows 上打的，所以服务端从 zip 取出的 `bytes` 要直接 `write_bytes`，
不要 `decode → 再 encode`。

## 4. 三条硬规则（这三条是这个接口存在的主要理由）

### 规则一：`cut.json` 永远不做整份覆盖（除非整卷重切）

`cut.json` 是整卷共用的（实测 21KB / 15 题），单题上传时它一定带着别的题的旧数据。
所以：**包内只允许 `cut.patch.json`，服务端按 `questions[].number` 逐项替换。**
manifest 显式声明 `"cut":"replace"` 才允许整份写，且此时 `base["cut.json"]` 必须匹配（防覆盖云端新切的数据）。

### 规则二：默认不删任何东西

`upsert` 模式下服务端只做「写入 + 覆盖」，没有删除路径。这条规则直接消掉 10-17 日志里记的那个
遗留风险：「云端切出来的子图只存在于服务器，本地 rsync 覆盖会删掉」。
真要清掉旧子图（比如某题从小问切分改回整题），走 `mode:"replace"`，而且 `dry_run` 会先把要删的列出来。

### 规则三：内容真变才撤确认

判定方式：提交前对每个将被覆盖的文件算现有 sha256，与包内比。

| 情况 | 动作 |
|---|---|
| 所有文件 sha256 全同 | `200 {status:"noop"}`，**不撤确认、不写审计变更、不动 mtime** |
| md 变了 | 撤该题全部单元的确认（切分题撤全部小问） |
| 只换了图、md 没变 | 也撤确认（老师核对的是老图），但 `flagged` 靠既有指纹机制自动失效 |
| 只有 `cut.json` 变了 | 不撤确认（切割数据不影响图的内容），但记审计 |

这套判定顺手修掉了日志 21:05 记的已知未修：「重传切好的卷不会让旧确认失效」。

## 5. 权限与审计

现有角色不够用，建议**新增一个能力位**而不是新角色：

```python
INGEST_ROLES = {"admin", "lead", "service"}   # 加进 auth.py
```

| 角色 | 能上传吗 | 理由 |
|---|---|---|
| admin / lead | ✅ | 管理和学科负责人 |
| service | ✅ | 给 AI / 脚本用的管道身份，本来就有 |
| tagger | ❌ | 上传会覆盖整题正本、影响别人标注，不能和「打标」同权 |
| viewer | ❌ | 只读 |

审计记录（`data/_audit/YYYY-MM-DD.jsonl`，复用 `auth.audit`）：

```json
{"at":"2026-10-17T22:50:11+08:00","user":"ai-tagger","via":"key",
 "action":"ingest.bundle","target":"2020-jan-wph11/q14",
 "extra":{"bundle_sha256":"...","bytes":189903,"files":3,"mode":"upsert",
          "force":false,"changed":["q14.md","assets/q14.webp"]}}
```
> 有了 `bundle_sha256` + 文件级 hash，任何时候都能回答「这道题现在这一版是谁传的、跟哪一版不同」。

## 7. 风险与反面意见

| 风险 | 说明 | 处置 |
|---|---|---|
| **单进程约束** | `uvicorn --workers 1`，上传会跟打标台抢 CPU | 上传路由用 `def`（走线程池，不阻塞事件循环）；单题包 2–3MB，无感；**整卷包不要走接口** |
| **nginx 32m 上限** | 整卷包（15 题 × 1.5MB + 子图）可能顶到 | 一期不放开；真要传整卷就 rsync |
| **能上传 = 能改正本** | 权限必须比打标更严 | `tagger` 不给；`force` 要在审计里显式标记 |
| **备份窗口** | 03:00 快照之前重传，没有回滚点 | 二期加「提交前把受影响文件复制到 `data/.ingest/undo/<uuid>/`」，保留 7 天 |
| **双写冲突** | 老师和接口同时改同一题 | 提交段持 `store._lock`；跨进程不存在（单 worker） |
| **别做成上传后端** | 一旦有人想用它传 PDF / 整卷，就会变成劣化版 S3 | 白名单硬拒 `source.pdf`，报错文案直接指向 rsync |

**我明确反对的一种做法**：把 `PUT /api/questions/{qid}/annotation` 扩展成能改文件。
那个接口的语义是「改标签」，混进文件上传会让审计、确认失效、权限三套逻辑纠缠在一起。新开 `/api/ingest/` 更干净。

## 10. 已采用的替代流程（不做接口，2026-10-17 定）

**规则：改任何已在云端产生过数据的题/卷，必须先从云端拉回来，再改，再传。**

```bash
P=2020-jan-wph11
S=ubuntu@140.143.229.85:/opt/qbank/data/edexcel/a-level/physics/$P/
L=data/edexcel/a-level/physics/$P/

rsync -av -e "ssh -i ~/.ssh/wpq.pem" $S $L    # 1. 先拉（服务器→本地）
# 2. 在本地这份上改
rsync -av -e "ssh -i ~/.ssh/wpq.pem" $L $S    # 3. 再传
```

- 第 1 步保留原 mtime，所以第 3 步 `rsync -a` 只会传真正改过的文件，天然增量。
- **永远不加 `--delete`**：云端按小问切出来的子图本地可能没有。
- **整卷重切前**先删该卷所有 `qNN-*.md` 与 `assets/qNN-*.webp`，否则旧子图基于旧整题裁剪，与新图不配套。
- 传完 `md` 后打标台立即可见（`read_meta` 按 mtime+size 校验），`/files/` 响应头是 `no-cache`，老师刷新即见新图，都不用重启。

### 单题重传后，三种状态各怎么处理

| 状态 | 存在哪 | 重传后 |
|---|---|---|
| 标签 / 难度 / 主标签 | 在 `qNN.md` 的 front-matter 里（**文件本身**） | 传新文件就等于旧标注没了；若本地那份带着旧标签，会跟着传上去 → **传前剥掉** |
| 审核确认（✓） | `data/_review/confirmed.json`，键 = 确认单元 id | **不会自动失效**（已知 bug），要手动删该题所有单元 |
| 此题有误 | `data/_review/flagged.json`，带文件指纹 | **自动失效**，不用管 |

只换图（不动 md）时：标签保留，但 `confirmed` 仍需手动撤——图变了钩不该亮。

## 附：如果只想要「最省事的 30 行版本」

```bash
#!/usr/bin/env bash
# 用法: ./push_one.sh 2020-jan-wph11 14
set -euo pipefail
P="$1"; Q=$(printf "q%02d" "$2"); D="data/edexcel/a-level/physics/$P"
R="ubuntu@140.143.229.85:/opt/qbank/$D"
# 1) 先把云端这题的文件拉回来（防止覆盖掉云端切的子图）

# 2) 只传这一题的文件，不带 cut.json（避免串味）
rsync -av -e "ssh -i ~/.ssh/wpq.pem" \
  "$D/$Q".md "$D/assets/$Q".webp "$D/assets/$Q".layout.json "$R/"
rsync -av -e "ssh -i ~/.ssh/wpq.pem" \
  "$D/assets/$Q".webp "$D/assets/$Q".layout.json "$R/assets/"
```
> 能用，但**它不校验**：图与 layout 配不配、cut.json 要不要更新、确认会不会假亮，全靠人。
> 接口的价值就在这里。要真做，建议直接上一期接口，别在脚本上叠补丁。

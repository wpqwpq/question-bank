# 主标签（primary_tag）实施方案

> 目标：接收方系统需要「每个题/每个小问恰好一个主标签」。本方案定义数据契约、接口契约、
> 打标台交互、AI 打标链路与存量处理。
> 状态：**设计已定稿**（决策见 §9），待按 §8 分阶段实施。

---

## 1. 需求评估

**结论：可行、成本低，建议现在就做（赶在打标铺开之前）。**

| 评估点 | 结论 |
| --- | --- |
| 与数据模型冲突 | 无。`tags` 是字符串数组，主标签只是其中一个的指针 |
| 是否需要新结构 | 不需要。front-matter 加一个标量字段即可，无需新表/新关系 |
| 存量迁移成本 | **0**（2026-10-16 实测：全库 1719 个题文件中仅 9 个带标签，`primary_tag` 出现 0 次；这批系测试数据，**已按决定清零**，全库现为「未打标」状态） |
| 后端改动面 | 2 个文件（`store.py` / `api.py`）+ schema 1 处，均为增量，不动 `compute_status` |
| 前端改动面 | 4 个文件，核心在 `TagPanel.tsx` 的 chip 内部结构 |
| 对 AI 打标的影响 | 必须同步：多标签题 AI 需挑主标签，否则写库被 422 拒 |

### 1.1 界面设想评估（「选中标签右侧多出可点区域」）

**可行，且你的判断是对的——按这个方向走。** 关键在实现位置：

| 做法 | 结果 |
| --- | --- |
| ✅ **在 chip 内部**加右侧区域（你的方案） | grid 列宽固定（`repeat(auto-fill,minmax(104px,1fr))`），chip 外框宽度不变 → **换行位置、标签相对位置完全不变** |
| ❌ 在 chip 外挂一个独立小按钮 | 需新增列宽或占位 → 必然改变换行点，与你的要求冲突 |
| ❌ 双击 chip 设主 | 不新增区域，但不可发现 |
| ❌ 在已选区（上方）点「设为主」 | 与「点击即移除」语义冲突 |

**唯一代价（必须先说清）：** 选中态 chip 内多出约 16px 热区，标签**文字可用宽度少 16px**，
长标签会更早触发 `truncate`。按现有词表中文标签长度（多为 4–8 字，列宽 104px）影响很小，但确实存在。

### 1.2 原设想未覆盖的三个边界（本方案已处理）

1. **降级**：标签从 2 个删到 1 个（且删掉的正是主标签）→ 剩下的自动接任，不留空状态；
2. **悬空引用**：主标签指向的 tag id 被词表删改后不再属于 `tags` → **读侧必须容错**，否则下游拿到假主标签；
3. **确认失效联动**（★ 最容易漏）：现有「保存后自动撤销我已核对」比的是 `(tags, difficulty)` 快照；
   只改主标签时会被判成「没变化」→ 确认勾选不撤销。`api._save_whole` 与 `api._save_split` 两处快照都要并入 primary。

## 2. 数据契约

front-matter 新增标量字段 **`primary_tag: <tag-id>`**（与 `tags` 同级）。

```yaml
---
id: aqa-a-level-physics-2019-jan-ph03-q01
...
tags:
  - u1-decay-equations
  - u1-half-life
  - u1-identifying-radiation
primary_tag: u1-half-life
difficulty: medium
---
```

### 2.1 唯一真源规则（写进 schema description，所有消费方共用）

| `tags` 数量 | `primary_tag` 落盘值 | 说明 |
| --- | --- | --- |
| 0 | 不写该键 | 无标签（保存被前置校验拦下，正常不会出现） |
| 1 | **由后端自动写成该 id** | 用户无需操作，界面也不显示主标签控件 |
| ≥2 | **必须显式提供且 ∈ tags** | 缺失 → 422 拒收 |

**读侧双保险**（下游/预览/AI 报告统一用这条回退，防手改与悬空引用）：

```
effective_primary = primary_tag ∈ tags ? primary_tag : (len(tags) == 1 ? tags[0] : null)
```

### 2.2 落盘位置

| 场景 | 写在哪 |
| --- | --- |
| 整题打标（`split_eligible=false` 或未开切分） | 主文件 `qNN.md` |
| 按小问打标（split） | 各子题文件 `qNN-<label>.md` 各带一份；主文件带 `split:` 标记时不带 tags/primary |

字段名备选：`primary_tag`（**推荐**）／`main_tag`／`primary_kp`。推荐理由：与 `tags` 并列语义直白、
snake_case 与全库一致、无歧义。

## 3. 后端改动（文件级）

| 文件 | 改动 | 风险点 |
| --- | --- | --- |
| `schema/question.schema.json` | properties 增 `primary_tag: {type:"string"}`，description 写 §2.1 规则 | `additionalProperties:true`，不加也通过；**加是为了让契约可读** |
| `workbench/backend/store.py` | ① `_strip_annotation_lines` 增 `^primary_tag:` 分支；② `_build_annotation_lines(tags,difficulty,primary_tag)`；③ `write_annotation()` 增第 4 参 + 归一；④ `build_sub_meta` / `save_split` 透传 | ★ ① 不加 → 关切分时旧 primary 残留在主文件；④ `_yaml_dump_meta` 无需改（标量自动走通用分支，且会排在 `tags:` 之前，符合约定） |
| `workbench/backend/api.py` | ① `SubAnnotation` / `AnnotationPayload` 增 `primary_tag: str \| None`；② 新增 `_validate_primary(tags, primary, where)`；③ `_save_split` / `_save_whole` 的 before/after 快照并入 primary；④ `get_question` 回传 `primary_tag` 与 `subs[].primary_tag` | ★ ③ 不做 → 确认失效联动漏判 |
| `workbench/backend/store.py`（读侧） | `Paper.questions()` 增 `primary_tag` + `primary_ready`（≥2 标签却无主标签时为 false） | `compute_status` **不动**：主标签不影响 done |
| `workbench/backend/api.py`（确认门禁） | `put_confirm` 增硬校验：单元 ≥2 标签却无主标签 → 422 | 现有「缺难度不能确认」只在前端实现，脚本可绕过；主标签这条**前后端双保险** |

### 3.1 接口契约

```jsonc
// PUT /api/questions/{qid}/annotation  整题
{ "tags": ["u1-half-life", "u1-decay-equations"], "difficulty": "medium", "primary_tag": "u1-half-life" }

// 按小问
{ "subs": [
    { "label": "1", "tags": ["u1-half-life"], "difficulty": null, "primary_tag": null },
    { "label": "2", "tags": ["u1-a", "u1-b"], "difficulty": "hard", "primary_tag": "u1-b" }
] }
```

- 请求 `primary_tag` 可为 `null`（单标签场景由后端补全）；
- 响应（`SaveResult`）新增 `primary_tag`；`GET /api/questions/{qid}` 的 `subs[]` 亦新增。
- 新增错误：`422 {where}: 多标签题必须指定主标签` / `422 {where}: 主标签必须是已选标签之一`。

| `App.tsx` | 状态 `draftPrimary` / `draftSubs[i].primaryTag`；`toggleTag` 维护降级；新增 `setPrimary`；save payload 带 `primary_tag`；`canSave` 增加「≥2 标签必须有主」条件；切题 / 切模式 / 切小问时回填与重置 |
| `components/PreviewPanel.tsx` | 标签行主标签加「主」badge + 左侧竖线加深；**只读，不提供修改入口**；「我已核对」勾选框的 `disabled` 条件由 `!hasDifficulty` 扩为 `!hasDifficulty \|\| !primaryReady`，并复用 `verifyColor` 的灰底提示样式（不新增配色） |

### 4.1 交互细则

| 情形 | 行为 |
| --- | --- |
| 选中 1 个标签 | 不显示右区；它自动即主标签（底部提示「主标签：<名>」或不提示均可） |
| 选中 ≥2 个标签 | 每个选中 chip 右侧出现 16px 热区（空心圆点）；点击 → 该标签变主（实心圆点 + 底色加深 + 字重 500） |
| 再点当前主标签的右区 | 无操作（≥2 时必须有一个主标签，不允许「取消」） |
| 取消勾选主标签 | 主标签置空；若剩余恰好 1 个标签 → 自动接任 |
| 取消勾选到 0 个 | 不可能（保存前置要求 ≥1 个标签） |
| ≥2 标签但未选主 | 「确定并保存」禁用 + 底部提示「请指定主标签」 |
| split 模式切换小问 | 右区状态随焦点小问切换（沿用 `focusIdx` 取 currentTags 的既有机制） |
| 预览模式 | 只读展示「主」标记，无右区 |

### 4.2 视觉规范（遵守项目硬规范：选中/状态类一律浅底+深字，不实心色块）

| 元素 | 样式 |
| --- | --- |
| 普通选中 chip | `border-blue-300 bg-blue-50 text-blue-700`（不变） |
| **主标签 chip** | `border-blue-500 bg-blue-100 text-blue-800 font-medium` + 右侧 7px **实心圆点** `bg-blue-600` |
| 非主（选中）右区 | 7px 空心圆点 `border-blue-300` |
| 已选区主标签 | 标签名前 5px 实心圆点（只读指示） |
| 预览模式主标签行 | 左侧竖线由 `blue-300` 加深为 `blue-600` + 「主」浅蓝 badge |

> 圆点是 5–7px 的**指示标记**，不是状态色块，不违反配色规范。

## 5. AI 打标链路（保留 AI 能力）

| 文件 | 改动 |
| --- | --- |
| `references/rules.md` | 新增「主标签怎么选」：多标签时挑**该题考核主线的那个**（通常是分值占比最大、或题干第一问的核心考点）；只标 1 个标签则可留空由后端补全 |
